# 개미굴 — 트러블슈팅 보고서 (초안)

인증/등급/출석/용어사전/챗/다크모드/회원탈퇴 기능 구현 과정에서 실제 브라우저 검증 중 발견하고
고친 문제들을 모았다. 전부 "일단 그럴듯해 보여서 넘어간" 게 아니라, Playwright로 실제 클릭·새로고침·
재시작을 재현해서 잡아낸 것들이다.

---

## 코드 버그

### 1. CORS에 DELETE 메서드 누락 — 회원 탈퇴가 조용히 실패

- **증상**: "네, 탈퇴할게요" 클릭 후 아무 반응 없이 그대로 마이페이지에 남음. 에러 메시지도 안 뜸
- **원인**: `backend/main.py`의 `CORSMiddleware`에 `allow_methods=["GET", "POST"]`만 있고 `DELETE`가
  빠져 있었음. 브라우저가 `DELETE /auth/me`의 프리플라이트(OPTIONS)를 거부하면서 실제 요청 자체를
  보내지 않음 — 서버 로그에 아무 기록도 안 남아서 더 헷갈리기 쉬운 유형
- **발견 경위**: 탈퇴 버튼을 실제로 눌러보고 URL이 안 바뀌는 걸 보고, Playwright 콘솔에서
  `Access to XMLHttpRequest ... blocked by CORS policy` 로그를 확인해 원인 특정
- **해결**: `allow_methods=["GET", "POST", "DELETE"]`로 수정. 신규 HTTP 메서드를 쓰는 엔드포인트를
  추가할 때마다 CORS 허용 목록도 같이 확인해야 함(재발 방지 포인트)

### 2. 마이페이지에서 로그아웃/탈퇴 시 리다이렉트 경합

- **증상**: 로그아웃 버튼을 눌렀는데 의도한 홈("/")이 아니라 로그인 페이지("/login")로 튕김
- **원인**: 마이페이지에 "로그인 안 된 상태면 /login으로 보낸다"는 가드 `useEffect`가 있는데,
  로그아웃 직후 `status`가 `unauthenticated`로 바뀌는 순간 이 가드가 먼저 반응해서
  `router.replace("/login")`을 호출하고, 그다음에야 원래 의도했던 `router.push("/")`가 실행되면서
  둘이 경합함(마지막에 실행되는 쪽이 이겨야 하는데 타이밍상 가드가 이김)
- **발견 경위**: 로그아웃 버튼 클릭 → URL 확인하는 실제 클릭 테스트에서 재현
- **해결**: `isLoggingOutRef`(useRef) 플래그를 로그아웃/탈퇴 시작 시점에 먼저 세워두고, 가드
  `useEffect`가 이 플래그를 보고 "지금은 의도된 이탈이니 개입하지 마라"고 판단하게 함

### 3. 안 읽은 메시지 배지가 새로고침 후 반영 안 됨

- **증상**: 챗을 한 번도 안 열고 새 브리핑이 쌓인 채로 재방문해도 배지가 안 뜸
- **원인**: 첫 방문 시 "지금까지 메시지는 이미 본 걸로 친다"는 기준값을 React state에만 저장하고
  `localStorage`엔 안 남겨서, 페이지를 새로고침하면 기준값이 다시 "지금 이 순간의 전체 메시지 수"로
  리셋됨 — 그 사이 쌓인 메시지가 통째로 "이미 본 것" 취급됨
- **발견 경위**: Playwright로 "닫힌 채 새로고침 → 배지 값 확인" 시나리오를 직접 넣어보고 기댓값과
  다른 걸 발견
- **해결**: 첫 방문 시 정한 기준값을 곧바로 `localStorage`에도 저장하도록 수정

### 4. 마이페이지 "등급 재검사 취소" 버튼 유실

- **증상**: 재검사 퀴즈를 시작한 뒤 되돌아갈 방법이 없음(끝까지 풀거나 새로고침 말고는)
- **원인**: 재검사 UI를 체크박스 폼에서 공용 스텝형 퀴즈 컴포넌트(`GradeQuizStepper`)로 교체하면서,
  기존에 있던 "취소" 버튼을 옮겨 담지 않고 누락함 — 리팩터링 중 흔한 종류의 회귀
- **발견 경위**: 버튼 높이 통일 작업 중 화면을 다시 살펴보다 자체적으로 발견(사용자 리포트 아님)
- **해결**: 마이페이지 쪽에 "취소하고 돌아가기" 버튼을 다시 추가(스텝퍼 자체는 그대로 두고 감싸는
  쪽에서 처리 — 재사용성 유지)

## 검증(테스트 스크립트) 과정에서의 실수 — 코드 버그는 아니지만 재발 방지용으로 기록

### 5. `127.0.0.1` vs `localhost` — 쿠키가 "안 실리는" 것처럼 보였던 문제

- **증상**: Playwright로 `fetch("http://127.0.0.1:8000/auth/me")`를 직접 호출했더니 401
- **원인**: 브라우저 쿠키 저장소 기준으로 `127.0.0.1`과 `localhost`는 다른 호스트로 취급됨.
  실제 로그인은 `localhost:8000`으로 이뤄졌는데 확인은 `127.0.0.1:8000`으로 해서 쿠키가 없는 게 당연했음
- **교훈**: 앱이 실제로 쓰는 호스트명과 정확히 같은 호스트로 검증해야 함. 이후 전부 `localhost`로 통일

### 6. Playwright route 가로채기가 프론트 페이지 경로까지 잡아먹은 문제

- **증상**: `/timeline` 페이지를 열었더니 화면에 JSON이 그대로 텍스트로 찍힘
- **원인**: 백엔드 API `GET /timeline`을 모킹하려고 `page.route("**/timeline*", ...)`처럼 와일드카드를
  너무 넓게 잡아서, 프론트(`localhost:3000/timeline`) 페이지 자체의 최초 문서 요청까지 같이 가로채
  JSON을 응답으로 내려버림
- **교훈**: 모킹할 땐 호스트까지 포함해서(`http://localhost:8000/timeline*`) 범위를 좁혀야 함

### 7. 로그인 페이지 컨테이너가 `flex-1`로 화면을 꽉 채우면서 생긴 거대한 빈 공간

- **증상**: 서브 페이지와 같은 스타일로 맞추려고 카드 컨테이너를 `flex-1`로 늘렸더니, 폼 내용은
  짧은데 카드만 화면 아래까지 쭉 늘어나 빈 공간이 큼(오히려 더 휑해 보임)
- **원인**: 캘린더/용어사전처럼 콘텐츠가 원래 많은 페이지의 레이아웃 패턴을, 콘텐츠가 짧은
  로그인/회원가입류 폼에 그대로 옮겨 적용
- **해결**: `flex-1`(늘리기) 대신 콘텐츠 크기에 맞춘 패딩(`py-10`~`py-14`)으로 변경

## 운영상 유의사항 (버그는 아니지만 반복됐던 것)

### 8. 새 엔드포인트 추가 후 백엔드 재시작 누락 → 404

- 백엔드는 `--reload` 없이 떠 있어서 라우터에 새 엔드포인트를 추가해도 코드에는 반영되지만
  **떠 있는 프로세스는 재시작 전까지 예전 라우트 테이블 그대로**임
- 즐겨찾기·탈퇴 사유 엔드포인트를 추가하고 바로 브라우저에서 테스트했다가 404를 보고 "버그인가?" 하고
  잠깐 헷갈렸던 경우가 있었음 — 실제로는 단순히 재시작을 안 한 것
- 앞으로 백엔드 라우팅/미들웨어(`main.py`, `routers/*.py`) 변경 후에는 검증 전에 재시작부터 확인
